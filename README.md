# 记账 · Android

本地优先的个人记账应用：记收支、看统计、管分类、设固定收支。数据只存在手机里，不联网、不上传，
支持 JSON / CSV 导出与恢复。

## 功能

| 能力 | 说明 |
| --- | --- |
| 记一笔 | 收入/支出、分类、金额、日期、备注；顶部显示今日支出、收入、结余 |
| 分类收藏 | 在分类管理里点星标，记一笔页面只先显示收藏的分类，其余收进「更多分类」 |
| 明细列表 | 按月浏览、收支筛选、备注搜索、点开可改可删 |
| 分类管理 | 新增/改名/改色/停用/删除，带「被引用就不能删、不能改收支归属」守卫 |
| 统计总览 | 日/月/年三种周期，收入、支出、结余 |
| 趋势折线 | 结余、收入、支出三条曲线，可点标签切换，默认只看结余 |
| 分类占比 | 环形图 + 横向占比条，颜色取自分类色 |
| 按到账日 / 按周期均摊 | 均摊把月度、年度固定收支摊到每一天，精确到分；统计页直接跟随「我的 → 统计方式」 |
| 固定收支 | 每天/每月/每年，月末与非闰年自动回退；支持暂停、结束日期、补记、立即检查 |
| 通知提醒 | 每日 / 每月两种，各自可设时间与开关，到点推一条收支小结到通知栏 |
| 桌面小组件 | 一行显示今天的支出、收入、结余，最小 3×1，点一下直接进 App |
| 备份 | 导出 JSON（完整账本）/ CSV（明细），导入 JSON 恢复，导入前会提示覆盖 |

金额一律以整数「分」存储，最多两位小数，单笔上限 999999999.99。

## 通知

在 **我的 → 通知** 里打开总开关（Android 13 及以上会请求通知权限），再按需打开：

| 类型 | 可配置 | 内容 |
| --- | --- | --- |
| 每日提醒 | 几点几分 | 当天收入、支出、结余 |
| 每月提醒 | 几号 + 几点几分 | 当月收入、支出、结余（日期超过当月天数时按月末） |

用的是 AlarmManager 的「允许唤醒」闹钟：能拿到精确闹钟权限就精确，拿不到就退化成不精确，
所以实际送达可能在设定时间前后几分钟，系统省电策略会进一步延后。开机和 App 升级后会自动重排闹钟。

几个使用细节：

- **首次打开**（Android 13 及以上）会问一次要不要开通知，点「暂不」就不会再打扰，之后可以在这一页重新打开；
- 打开开关后，每一项下面会显示**下次提醒的具体时间**（如「明天 15:00」），能立刻看出有没有排上；
- 系统没给「闹钟和提醒」权限时，卡片顶部会出现一条提示和「去允许」按钮；
- 通知走「收支提醒」渠道，重要级别为高，会弹出来而不是只躺在通知栏；
- 「发一条测试通知」会立刻发出，并回报**实际结果**（已发送 / 系统关闭了通知 / 渠道被关闭 / 没有权限），不再只说一句「已发送」；
- 「通知设置」按钮直达本应用的系统通知页，方便检查是不是被系统关了。

## 桌面小组件

长按桌面 → 小组件 → 记账，选「今日收支」。三个指标并排（标签在上、金额 22sp 窄体加粗），点击进入 App。

- 最小可以缩到 3×1，默认放置为 3×1；宽度拉到 4 格时列间距会自动变宽。
- 数字保证 3 格宽也不会被截断（含「-305.87」这样的负数）；整数不带 `.00`。
- 刷新时机：桌面 30 分钟的系统刷新、App 启动、以及每次记账/删除/补记固定收支之后。
  所以刚记完一笔，回到桌面通常立刻就是新数字。

## 统计方式

在 **我的 → 统计方式** 里选一次，统计页就按这个口径展示，不再重复选择：

- **按到账日**：每月 15 号发工资，整笔工资就算在 15 号；
- **按周期均摊**：把月度固定收支摊到自然月每一天、年度固定收支摊到自然年每一天，
  手动收支和每日固定收支仍按当天算。「含未到账计划」打开后，发薪日前也能看到每天的工资份额。

均摊的余数分依次分给周期前几天，任意区间求和都能精确回到周期总额。

## 分类收藏

在 **我的 → 分类管理** 里点每行右侧的 ☆ 收藏，再点一次取消。

记一笔页面会先显示收藏的分类；没被收藏的收在「更多分类（N）」里，点开才展开。
收入和支出各用各的收藏。一个都没收藏时，分类照常全部平铺，不会出现「分类不见了」。
收藏只是本地偏好，不写进账本，也不随备份迁移。

## 固定收支

在 **我的 → 固定收支** 里新建规则：名称、分类、金额、周期、开始/结束日期、备注。

| 周期 | 行为 |
| --- | --- |
| 每天 | 生效范围内每天记一笔 |
| 每月 | 选择每月几号；设为 31 号时，没有 31 号的月份记在月末 |
| 每年 | 选择月份和日期；2 月 29 日在非闰年记在 2 月 28 日 |

几条刻意的语义：

- **补记**：错过的执行日按原计划日期补上，不会挤到当天；
- **幂等**：每条「规则 + 日期」只会生成一次。你手动删掉某笔之后，重新检查也不会把它再生成一遍；
- **暂停**：暂停期间不生成，恢复后只从当天往后算，不补暂停期的账；
- **改规则不追溯**：改金额或分类从当天生效，历史记录保持不变；每次改动都留一条不可变版本，
  统计里的历史均摊仍按当时的版本算；
- **删除**：规则归档，已生成的记录保留。

生成时机：打开 App 补一次，后台每 6 小时巡检一次，规则页还有「立即检查」。
国产 ROM 的省电策略可能让后台检查延后，打开 App 时的那次补记可以兜住。

## 技术栈

- Kotlin 2.0.21 + Jetpack Compose（Material 3）+ Room 2.6.1（KSP）
- minSdk 26 / targetSdk 35，JDK 17
- WorkManager 2.9.1 负责固定收支的后台补记；AlarmManager 负责通知提醒；小组件用 RemoteViews
- 没有引入图表库：环形图与折线图是几十行 Canvas 画的，包体小、行为可控
- 没有引入 Hilt：依赖链只有 `AppDatabase → Prefs → LedgerRepository / RecurringRepository → AppViewModel`

## 目录结构

```
app/src/main/java/com/qsc/accounting/
├── core/            金额（分）、日期、校验错误
├── data/
│   ├── db/          Room 实体、DAO、数据库
│   ├── model/       收支方向、周期、来源、统计方式等枚举
│   ├── Records.kt   筛选条件、分页、输入模型
│   ├── Prefs.kt     统计方式、分类收藏等本地设置
│   ├── LedgerRepository.kt     记账、分类守卫、统计装载、导出
│   ├── RecurringRepository.kt  固定收支的规则、版本历史与到期生成
│   └── BackupCodec.kt          JSON 备份的读写与旧版本兼容
├── domain/          纯逻辑：均摊算法、统计窗口、统计引擎、固定收支日期规则
├── notify/          通知渠道、提醒排程与接收器
├── widget/          桌面小组件的数据装配
├── work/            WorkManager 后台任务
└── ui/              Compose 界面
```

`domain/` 不依赖 Android，可以直接跑单元测试。几条关键不变量都在测试里：

1. 汇总范围与趋势范围分离，趋势永远裁到今天；
2. 均摊的余数分依次给周期前几天，任意区间求和能精确回到周期总额；
3. 已执行的固定收支不会因为「含未到账计划」被重复计算；
4. 固定收支生成是幂等的：同一（规则, 日期）只会有一笔，用户手动删掉也不会被重新生成；
5. 暂停期间不生成，但游标照常推进——恢复后不会补出暂停期的账。

## 构建

需要 Android Studio（Ladybug 或更新）或命令行环境（JDK 17 + Android SDK 35）。

```bash
# 打开工程
# Android Studio: File → Open → 选择本目录

# 或命令行
./gradlew :app:assembleDebug        # 产物 app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest    # 单元测试 + 真库集成测试
```

工程自带 wrapper（`gradle/wrapper/gradle-wrapper.jar`），不要删。首次同步会下载 Gradle 8.9 与依赖。

`settings.gradle.kts` 里把阿里云镜像放在了官方仓库前面——Gradle 插件门户在国内经常超时。
如果你在墙外或企业内网有自己的仓库，直接删掉这几行 `maven("https://maven.aliyun.com/...")` 即可。

当前工程已在 JDK 17 + Gradle 8.9 + AGP 8.7.2 + Kotlin 2.0.21 下验证：`assembleDebug` 通过，
产出约 10 MB 的 debug APK；`testDebugUnitTest` 54 个用例全部通过，其中 16 个跑在 Robolectric 上
（固定收支生成、备份往返、通知排程、图表与小组件渲染快照）。

集成测试第一次跑时，Robolectric 会下载对应 SDK 的 `android-all-instrumented` 包（约 200 MB）。
网络受限时可以手动把 jar 放到某个目录，然后：

```bash
JAVA_TOOL_OPTIONS='-Drobolectric.offline=true -Drobolectric.dependency.dir=/path/to/jars' \
  ./gradlew :app:testDebugUnitTest
```

## 数据与备份

账本存在应用私有目录的 `accounting.db`（SQLite），卸载应用会一并删除，换机或重置前先导出。

- **导出 JSON**：完整账本，包括分类、记录、固定规则、均摊快照与执行凭据，用于恢复；
- **导出 CSV**：当前月份的明细，带 BOM，Excel 打开不乱码；
- **导入 JSON**：替换现有账本，导入前会二次确认。

旧版本导出的 JSON 备份也能导入（缺少均摊快照的会按规则频率补齐）。
